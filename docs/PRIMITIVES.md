# Primitive and helper wrappers (E2E-17, in progress)

This package lists every KLambda primitive and every registered port primitive
of the two pinned ports. For each one it records the exact implementation and
the dependency closure down to individually named host operations. It then
proves a first batch of wrapper bodies from their captured bytes.
"Proved" always means: the actual pinned definition, read from its exact
bytes, satisfies the stated KLambda rule for every host operation table that
satisfies the individually named host contracts. The host operations
themselves (Chez `eq?`, SBCL `EQ`, `+`, `TYPEP`, ...) remain contracts owned by
E2E-21..27. Nothing here proves Chez, SBCL, the readers, the garbage collector
or generated machine code.

## The matrix (`spec/primitives.json`)

The matrix is generated by an inert Shen capture tool:
`shen/primitive-inventory.shen` lexes the vendored source bytes itself, with
no Shen reader, host reader, macroexpansion or eval.
`shen/primitive-table.shen` holds the reviewed roots and evidence labels, and
`shen/primitive-json.shen` renders the result. `make test`
(`tests/primitives.shen`) regenerates the matrix and requires it to be
byte-identical to the checked-in file.

| Port | Revision | Sources read |
|---|---|---|
| shen-scheme | tizoc/shen-scheme `8d261518` | `ports/upstream/primitives.scm` (blob `92b8875a`), `chez-prelude.scm` (`18d1ce9a`), `overrides.shen` (`3f20b5f1`); compiler `compiler.shen` (`42ac753b`) |
| shen-cl | Shen-Language/shen-cl `4844072d` | `ports/upstream/shen-cl/primitives.lsp` (`f9b11c8a`), `overwrite.lsp` (`8108c9d4`); compiler `compiler.shen` (`2d624377`) |

`scripts/check-upstream-pass.py` checks every blob id. The Shen-CL files
are vendored under the BSD licence in `LICENSES/Shen-CL.txt`.

Each entry (114 in total: 46 Shen-Scheme, 68 Shen-CL) records:

- `rule`: the formal rule slot in `rocq/KLSemantics.v`, for example
  `rule_equal`, `rule_arith PMul` or `rule_div`. A port extra names the
  KLambda rule it serves.
- `implementation`: a definition with its file, blob, name and byte span, or
  the compiler clause that inlines host operations, with the exact operations
  it emits (for example Shen-Scheme `pos` gives `(string (string-ref S N))`).
- `closure`: the transitive dependency closure, computed from the source
  bytes. It lists the definitions reached, the Shen-level functions called
  (compiled kernel code, owned by E2E-15/16), and every remaining host
  operation, named individually with its owner. There are 252 distinct
  operations: E2E-21 representations, E2E-22 Chez syntax, E2E-23 SBCL special
  forms, E2E-24 runtime routines, E2E-25 allocation, E2E-26 eval/compile and
  E2E-27 OS/IO/clock. The closure is conservative. It counts every unbound
  symbol in evaluated position, over-approximates binders, and honours SBCL
  read-time conditionals as the SBCL reader would.
- `evidence`: `proved` (with theorems in `rocq/Audit.v` or a lane audit
  module `rocq/Audit_<lane>.v`), `contract-assumed` (the primitive is a direct
  host operation), `sampled` or `none`.

The `contracts` section (150 entries) gives a name to every primitive
contract that is currently assumed anywhere in the repository. Each entry has
a host operation, an owner and a status:

### Checker (`shen/primitive-matrix.shen`)

The checker reads the matrix as inert JSON. It rejects the matrix when:

- a KLambda primitive is missing for a port. The 36 names are read from
  `prim_name` in `rocq/KLSyntax.v`.
- a registered port primitive is missing. This set is recomputed from the
  sources. For Shen-Scheme it is every `kl:` definition in `primitives.scm`,
  plus every `primitives.scm` definition the compiler package names. For
  Shen-CL it is every `primitives.lsp` function or macro whose name is a
  KLambda primitive, a `compiler.shen` symbol, or `shen-cl.` plus a
  `compiler.shen` symbol.
- an entry is duplicated, or an entry has no implementation.
- the evidence kind is unknown.
- a `proved` entry cites no theorem, or cites a theorem missing from
  `rocq/Audit.v` and the lane audit modules.
- a host operation is not owned by one of E2E-21..27.
- a field of a named contract record, a `Native.primitive` operation or a
  profile slot has no contract entry. The checker reads these from the Rocq
  sources.

`tests/primitives.shen` runs thirteen hostile variants and requires each one
to be rejected (the two newest drop the `cl_host_ops.host_eq` contract and
cite an unaudited lane theorem). Acceptance is bookkeeping only; the theorems
are checked by `make prove`. Audited names are read from `rocq/Audit.v` and
the lane audit modules listed in `buri.laudit-lane-files` (`shen/ledger.shen`).

## First proved batch

Capture discipline: `scripts/package-primitives.py` copies the exact
definition bytes from blob-checked files into `rocq/PrimitiveSources.v`, and
records their spans. `scripts/check-primitives-package.py` independently
re-checks the literal against the source bytes. `make prove` regenerates the
package and diffs it. `rocq/PortReader.v` is an independent, rejecting Rocq
reader for the Scheme and CL subsets. Admission (`scheme_wrappers_admitted`,
`cl_wrappers_admitted`) is computed equality of the decoded definitions with
the reviewed AST, and the theorems interpret the admitted AST. Nine altered
copies of the bytes are refused (`tests/mutate-primitives.py`): `eqv?` for
numbers, a wrong assert predicate, a dropped tail comparison, a swapped
Boolean, `EQ` for numbers, a ratio escape, a wrong zero product, `EQ` in
`numeric-equal`, and `1-` in the bignum branch of `increment`. The package
now also carries `shen-cl.increment` and `shen-cl.decrement`.

### Shen-Scheme (`rocq/SchemeWrappers.v`)

All results below are universal theorems over every Chez operation table that
satisfies the named contracts. Fuel bounds are explicit.

- `assert_boolean_body`: the captured `kl:_scm.assert-boolean` returns a
  Boolean unchanged. On any other value it calls `error` (the `raise-error`
  `syntax-rules` macro, admitted from `chez-prelude.scm`).
- `guarded_if`: `(if (kl:_scm.assert-boolean T) A B)` is the KLambda `if`
  rule. True runs only A, false runs only B, and any other value raises
  before either branch (XNotBoolean).
- `kl_eq_data`: on first-order data (exact integers, symbols, strings,
  Booleans, `()` and pairs) the captured `kl:=` returns
  `Boolean (same a b)`, with the state unchanged and no events.
- `stock_equality_refines_rule`: through the representation `rep_s` (ASCII
  names), `kl:=` answers exactly what `KLSemantics.rule_equal` answers.
- `stock_matches_replacement`: on data, the stock `kl:=` equals the sealed
  and EQ-1 replacement `(equal? x y)`. This bridges the `kl:=` half of
  EQ1-NUMERIC.
- `stock_mixed_exactness`: if Chez `=` identifies 1 with an inexact 1.0, the
  stock wrapper answers true while `equal?` answers false.
- `model_ops_satisfiable`: one concrete table satisfies every contract, so
  the theorems are not vacuous.

Open: the vector branch (`vector=?` is a `do` loop; it is captured but not
decoded, and the decoder rejects it), closures, inexact numbers, and native
Chez execution.

**Confirmed defect boundary (sampled).** The literal path of
`emit-equality-check` emits `eqv?` when either operand is a numeric literal.
On Shen-Scheme, `(= X 1)` with X the inexact 1.0 answers false through that
path and true through `kl:=`, and `eval-kl` takes the literal path too
(`tests/primitives.shen`). The candidate disagreement recorded in
VALUE-MODEL is therefore confirmed natively for compiled code
(`OB-SCHEME-EQ-LITERAL`, refuted). The literal lowering is safe exactly when
the other operand is not an inexact number.

### Shen-CL (`rocq/CLWrappers.v`)

- `cons_wrapper`, `string_wrapper`, `number_wrapper`, `comparison_wrappers`
  and `equal_wrapper` work in CLLowering's relational CL model, whose
  primitive relation runs the captured wrapper bodies. In test position,
  each wrapper is the CL test of its host predicate. These discharge
  `CLLowering.primitive_contracts` fields `pc_cons`, `pc_string`,
  `pc_number`, `pc_greater`, `pc_greater_eq`, `pc_less`, `pc_less_eq` and
  `pc_absequal` *at the arity the optimizer emits*. Wave B found that the
  record stated these fields for every argument list, which the bodies cannot
  justify. Wave C narrowed the record; see the next section.
- `absequal_data` uses a small functional CL evaluator quantified over every
  table satisfying `sbcl_equality_ops`. On first-order data (symbols,
  strings, canonical integers, NIL, conses) the captured `absequal` answers
  `T` exactly when the data are equal. `equal_data` lifts this to the Shen
  Booleans of `shen-cl.equal?`.
- `eq_rewrite_safe` and `eq_rewrite_unsafe` cover the defect found in Wave A.
  The optimizer rewrites `(shen-cl.equal? X 'D)` to `(EQ X 'D)`. That
  rewrite is exact for every data X when D is a symbol or NIL. For every
  non-symbolic data D (a cons, string or number), a contract-satisfying
  host exists in which `EQ` answers NIL while `absequal` answers T. The safe
  domain is therefore exactly `CLLowering.qsafe`. SBCL answers NIL for a
  fresh equal list, a fresh equal string, and `(EQ 1 1.0d0)`
  (`ports/shen-cl-primitive-samples.lisp`).
- Arithmetic theorems `add_int`, `subtract_int`, `multiply_int`,
  `divide_int` and `arith_refines_rules` hold for every exact integer pair,
  fixnum or bignum, any signs. The wrappers return the exact
  `rule_arith` result. `shen-cl.divide` gives the exact quotient, the
  DIVISION-BY-ZERO condition for divisor 0, or the host double nearest x/y.
  It never returns a CL ratio. KLambda agrees in the non-integral case
  exactly when the `int_div_inexact` slot is pinned to that conversion.
  Shen-Scheme gives the same answer from `non-rational-/`, where the Chez
  `inexact` slot is proved in StockDivisionGeneral. The VALUE-MODEL numeric
  difference is resolved: both ports return integers when the division is
  exact, and a host conversion slot otherwise.
- **Discovered divergence:** `multiply_zero_absorbs_symbol`. `(* 0 true)`
  answers 0 in Shen-CL, where KLambda's `*` rule is a domain error. It holds
  for every contract-satisfying host and is observed on SBCL 2.6.8
  (`OB-CL-MULTIPLY-DOMAIN`, refuted). Shen-Scheme raises
  (`tests/primitives.shen`).
- `model_equality_ops` and `model_arith_ops` show the contracts are
  satisfiable.

### The lowering's contracts from the captured bodies (`rocq/CLContracts.v`, Wave C)

**Narrowing (a false requirement removed).** `CLLowering.primitive_contracts`
used to state its nine predicate fields as `pred_refines f g`, that is, for
every argument list. The optimizer never emits a wrong-arity call: each
clause's source pattern fixes the operand count (`[cons? X]` has one,
`[greater? X Y]` two). And the captured wrapper body cannot justify the
all-arity form. Called with the wrong number of arguments, `cons?` has no
outcome of its own in the model. In SBCL it raises a fresh program-error
that names `cons?`, while `CONSP` raises a different condition.
`all_arity_unjustified` proves the field false in every world that runs the
captured body and where `CONSP` raises at that arity. `captured_all_arity_false`
proves the same for the captured world whenever the host raises.

The record now states each field at exactly the emitted arity and shape.
`sem_pred1` and `sem_pred2` replace `sem_pred` in `optimise_sound`, and
`optimise_sound` and `emit_if_refines` are re-proved unchanged in statement.
`pred_refines_narrows` shows that the old fields imply the new ones, so every
world admitted before is still admitted. This is a strengthening of the
theorems' applicability, not a weakening.

**The bridge.** `captured_prim St h kern other` is a relational world for
CLLowering's `ev`:

- the eight Boolean wrappers run their captured bodies relationally
  (`CLWrappers.wrapped`);
- `shen-cl.absequal` and `shen-cl.numeric-equal` run their captured bodies in
  the functional `ceval`. A call's outcome is the result on which the
  fuel-indexed evaluation stabilises (`run_helper`, `eventually`);
  `helper_value` turns any "for all fuel ≥ 10" theorem into that outcome;
- the kernel functions `not`, `empty?` and `fail`, which have no
  `primitives.lsp` body, are a relation `kern`;
- every other head is a host table `h`. Exhausted fuel and unsupported forms
  give no outcome; they are never values.

All results are universal theorems, for every state type, every relation
for unmodeled forms, and every `h`, `kern` satisfying the named records:

- `abs_symbolic_right/left`, `abs_string_right/left`: for **every** value `v`
  (not only first-order data), the captured `absequal` against a symbol or
  NIL, or against a string literal, in either operand order, answers
  `hb (sv_eqb …)`. That is exactly what `EQ`, `NULL` or `EQUAL` answer there.
- `abs_numeric_right/left`, `numeric_equal_value`: for every value and every
  numeric literal, `absequal` (either order) and `numeric-equal` (with the
  optimizer's operand swap) return the same result, `num_spec`. Both reach the
  same host `=`, so floats and mixed exactness need no assumption beyond `=`'s
  symmetry and reflexivity on literals.
- `captured_contracts`: every field of the narrowed record holds in
  `captured_prim`. Eight fields need no host premise, because the wrapper is
  equivalent to its host predicate whatever that does: `pc_cons`,
  `pc_string`, `pc_number`, the four comparisons and `pc_absequal`. Six are
  reduced to `cl_host_ops` alone: `pc_cl_not`, `pc_null_right/left`,
  `pc_string_equal`, `pc_numeric` and `pc_symbol_eq`. Three also use
  `cl_kernel_ops`: `pc_not`, `pc_empty` and `pc_fail`.
- `discharged_optimise_sound`, `discharged_emit_if_refines`: the captured
  `optimise-boolean-check` and `emit-if` theorems in `captured_prim`. Each is
  conjoined with `cl_wrappers_admitted`, so the bodies are the admitted
  decoding of the pinned bytes. The only hypotheses left are `cl_host_ops`,
  `cl_kernel_ops` and the theorem's own `qsafe`. `SbclHostOps.sbcl_optimise_sound_e24`
  and `sbcl_emit_if_refines_e24` replace the ten E2E-21 fields of
  `cl_host_ops` by the representation-level theorems, leaving `cl_e2e24_ops`
  and `cl_kernel_ops` ([REPRESENTATION](REPRESENTATION.md) 5.5).
- `increment_int`, `decrement_int`, `step_refines_rules`: the captured
  `shen-cl.increment`/`decrement`, now packaged and admitted, return z+1 and
  z-1 for every integer. These are `rule_arith`'s answers for the
  `(+ 1 X)`, `(+ X 1)` and `(- X 1)` that `optimise-static-application`
  replaces. Premise: `cl_step_ops` (`TYPEP` gives a Boolean, `1+`/`1-` exact
  on integers). `ceval` evaluates `(THE type x)` as `x`.
- `model_host_ops`, `model_kernel_ops`, `model_step_ops` and
  `model_world_contracts` show the records are satisfiable (anti-vacuity, not
  SBCL).

**Contracts that remain**, each named individually in `spec/primitives.json`:

- `cl_host_ops` (16 fields). E2E-21 owns `EQ`, `TYPEP FIXNUM`, `INTEGERP`,
  `NUMBERP`, `CONSP`, `STRINGP`, `ARRAYP`, `SYMBOLP`, `NOT` and `NULL`.
  E2E-24 owns `STRING=`, `EQUAL` (string and object cases), `EQL` versus `=`
  on integers, and `=` symmetry and reflexivity.
- `cl_kernel_ops` (3, E2E-16): kernel code compiled by Shen-CL.
- `cl_step_ops` (3, E2E-21/24).
- Modeling boundary, not a hypothesis but a limit of the instantiation:
  - the host operations in `fn_heads` are pure functions of their arguments;
  - a raised host condition is a function of the arguments, so fresh
    condition identity is quotiented;
  - `VObj` values are not numbers, symbols, strings or conses;
  - no `VNum` spelling denotes NaN.
- `FORMAT` printer effects (`CLPortGuard.format_printer`) and the quotiented
  Boolean-error text, both unchanged.

Mutation cases: two admission mutants (above) and three restated claims
refused by Rocq (`tests/mutate-cl-contracts.py`):

- the all-arity `cons?` field for the captured world;
- `numeric-equal` without the operand swap;
- `EQ` in place of `EQUAL` against a string literal.

Open: `cf-vectors` (a LOOP body outside the model) for two vectors, floats in
the arithmetic wrappers, every `none` entry in the matrix, and all host
operation contracts.

## Wave-D batch: intern, strings and vector reads

Packaging uses the same discipline as above. `scripts/package-prims2.py`
copies blob-checked definition bytes into `rocq/Prims2Sources.v`. These are
stock and patched `kl:intern`, and the Shen-CL `|intern|`, `|pos|`,
`|tlstr|`, `|n->string|`, `|string->n|` and `|<-address|`.
`scripts/check-prims2-package.py` re-checks every literal. `make prove`
regenerates and diffs the package. The patched `primitives.scm` comes from
`package-patched.py apply`, which now also applies
`ports/patches/shen-scheme-primitives.diff`.

### Shen-Scheme `kl:intern` (`rocq/SchemeIntern.v`)

These are universal theorems over every Chez table that satisfies
`chez_intern_ops`. Its seven fields are `equal?` on strings,
`string->symbol`, `string-length`, `>`, `string-ref` at 0, `char-numeric?`
on ASCII characters, and `string->number` (which answers `#f` or a number).

- `stock_intern_body` is the exact denotation. `stock_intern_digit_led`
  and `stock_intern_twelve` show the divergence from `rule_intern`: a name
  that is digit-led with length > 1 and that the host reads as a number is
  returned as that number. OB-SCHEME-INTERN-NUMERIC stays refuted.
- `stock_patched_agree`: on every other name, stock equals patched.
- `patched_intern_body`, `patched_intern_symbol` and
  `patched_intern_refines_rule`: the patched body refines `rule_intern` for
  every string. This is OB-SCHEME-INTERN-PATCH.
- `model_intern_ops` shows the contracts are satisfiable.

The compile-time fold `[intern S] -> [quote (intern S)]` runs the compiling
image's `kl:intern`. No theorem here covers it.

### Shen-CL strings, vector read and intern (`rocq/CLStrings.v`)

The bodies run in `CLWrappers.ceval`. The theorems quantify over every host
table that satisfies `CLContracts.cl_host_ops` (for `STRINGP`, `NOT` and
`INTEGERP`) and the new records:

- `cl_string_ops`: `LENGTH`, `PLUSP`, `MINUSP`, `>=`, `<` and `=` on
  integers, `SUBSEQ`, `CHAR`, `CHAR-CODE`, `MAKE-STRING`, `CODE-CHAR` and
  `ERROR`. Characters are abstract (`chr`, `cchar`).
- `cl_vector_ops`: `SVREF` in range and out of range (safety 3).
- `cl_intern_ops`: `INTERN`, plus the uncaptured `shen-cl.process-intern`.

The modeling boundary is stated in the module. The environment binds the CL
constants `:INITIAL-ELEMENT` (to itself) and `CHAR-CODE-LIMIT` (1114112,
the pinned SBCL image value). A raised condition is quotiented. Strings are
ASCII. `refines` means one of two things: both sides return represented
values with the store unchanged, or the rule throws and the body raises.

| Theorem | Statement |
|---|---|
| `pos_refines` | every represented argument pair |
| `tlstr_body_spec`, `tlstr_refines` | every represented argument; `""` and non-strings raise |
| `string_to_n_refines` | unit and empty strings, non-strings |
| `string_to_n_long` | **divergence**: length >= 2 raises; the rule answers the first code point (OB-CL-STRING-TO-N-UNIT) |
| `n_to_string_refines`, `n_to_string_scalar` | ASCII codes, out-of-range integers, non-integers; every scalar value is accepted by both |
| `n_to_string_surrogate` | **divergence**: a surrogate returns a string; the rule is a domain error (OB-CL-N-TO-STRING-SURROGATE) |
| `get_address_svref`, `get_address_refines` | `<-address` is exactly `SVREF`. It refines `rule_address_get` (element, or a raise where the rule throws `XBounds`) for every heap vector represented element-wise by the host vector. That correspondence is an E2E-21 premise. |
| `intern_body_plain`, `intern_refines` | names without `#`, `'`, `` ` `` and `|`; `"true"`/`"false"` give the Boolean symbols |
| `model_strings_ops` | one table satisfies all four records (anti-vacuity, not SBCL) |

These results discharge OB-CL-STRING-PRIMS on the stated domains.
