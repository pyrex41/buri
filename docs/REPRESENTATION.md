# Native representation relations (E2E-21, Waves C and D, in progress)

This is the first E2E-21 deliverable. It covers the Chez Scheme 10.3.0
`tarm64le` object representation, which Shen-Scheme v0.52 uses. The
representation is defined against the KLambda value model of
[VALUE-MODEL](VALUE-MODEL.md) (`rocq/KLValue.v`).

* For Chez there is a **source-bound specification** of every value kind Shen
  uses, and a **Rocq representation relation** with proved basic properties.
* The Islaris fast-path theorem of [ARM-FOUNDATION](ARM-FOUNDATION.md) 10.3
  is restated as a statement about Shen integers.
* For SBCL 2.6.8 arm64 there are representation relations for KLValue and for
  the CL-model values, and the ten E2E-21 host operations of
  CLContracts.cl_host_ops are proved against the captured inline type-test
  code (section 5, Wave D).

Evidence kinds are kept apart throughout:

* **universal theorem**: a Coq 8.18 proof in `scripts/prove`, closed under
  the global context;
* **ground derivation**: a closed computation on the pinned constants;
* **sampled**: one emulated process or one host run;
* **Islaris theorem**: separate Coq 8.19 toolchain, relative to isla traces.

The extractor is inert. It reads `#define` lines from the generated
`equates.h` and literal `define-constant` forms from `cmacros.ss`. From the
`define-registers` form of `arm64.ss` it takes the registers, applying the
argument-register rule of `np-register.ss`: the first `asm-arg-reg-cnt`
non-fp "extra" registers are the argument registers. From `types.h` it checks
the `TYPE` macro text. For SBCL it evaluates the lowtag and widetag `defenum`
forms and resolves `#+`/`#-` against the feature set recorded in the image
capture. It writes only `Definition name : Z := value.` lines to
`rocq/ChezLayout.v` and `rocq/SbclLayout.v`. `scripts/prove` regenerates both
files and diffs them against the committed ones.

The extractor never compares sources with each other. Rocq checks every
cross-source agreement as a lemma:

* `cmacros.ss` against `equates.h`;
* the SBCL source evaluation against the image capture;
* the sample against the encodings.

## 2. Chez 10.3.0 tarm64le object representation

All values below come from the generated `equates.h` unless marked.
`TYPE(x,t) = x - typemod + t` (`c/types.h:289`). An object at a 16-byte
aligned address `A` (`byte_alignment` = 16) therefore has the pointer
`A - 8 + t`, and a pointer satisfies `w mod 16 = t + 8`. The sample confirms
this: pair 9, flonum 10, symbol 11, closure 13, typed objects 15. A field
displacement `disp` reads the byte at `A + disp + t - 8`.

| Kind | Representation | Constants |
|---|---|---|
| Word | 64 bits, little endian | `ptr_bits` 64, `ptr_bytes` 8, `typemod` 8, primary tag = low 3 bits |
| Fixnum | `z * 8 mod 2^64`, tag `000` | `fixnum_bits` 61, `fixnum_offset` 3, `mask_fixnum` 7, range [-2^60, 2^60-1] |
| Booleans | `#f` = 0x06, `#t` = 0x0E (`type_boolean` 6, mask 0xF7) | immediate tag `110` |
| Empty list, void, unbound, eof, bwp | 0x26, 0x2E, 0x1E, 0x36, 0x4E; black hole 0x46, forward marker 0x3E | immediates |
| Character | `code << 8 \| 0x16` (`char_data_offset` 8, `type_char` 0x16) | immediate |
| Pair | tag `001`; car at disp 7, cdr at disp 15; 16 bytes | `pair_car_disp`, `pair_cdr_disp`, `size_pair` |
| Flonum | tag `010`; IEEE binary64 at disp 6 (offset 0, no header); 16 bytes | `flonum_data_disp`, `size_flonum` |
| Symbol | tag `011`; value 5, pvalue 13, plist 21, name 29, splist 37, hash 45; 48 bytes | interned name is a string (sampled) |
| Closure | tag `101`; disp 3 holds the **entry address** = code object + `code_data_disp` (65); free variables from disp 11 | `CLOSCODE`, sample `closure-entry-minus-code` = 65 |
| Typed object | tag `111`; type word at disp 1 | |
| — vector | header `len << 4 \| imm << 3 \| 0` (low 3 bits = `type_vector` 0); elements at disp 9 + 8i | `vector_length_offset` 4, `vector_immutable_flag` 8 |
| — string | header `len << 4 \| imm << 3 \| 2`; elements are 32-bit **string-chars** at disp 9 + 4i, each the low half of a Chez char: `code << 8 \| 0x16` | `string_char_bits` 32, `string_length_offset` 4 |
| — bignum | header `len << 6 \| sign << 5 \| 6` (mask 0x1F); 32-bit bigits from disp 9, **most significant first** (`c/number.c` `BIGIT(x,0)`) | `bignum_length_offset` 6, `bignum_sign_offset` 5 |
| — code | type word low byte 0xBE | `type_code`, `mask_code` 0xFF |
| — port | type word low byte 0xDE | `type_port` |
| — record / condition | type word is an rtd pointer: low 3 bits 7 | `type_record`, `record_type_disp` 1 |

**Strings versus the VALUE-MODEL string profile.** A Shen string is a list of
code points, each a Unicode scalar value. Chez stores one 32-bit unit per
character, `cp * 256 + 0x16`, so 24 bits of code point plus the char tag.
`string_at` requires every element to have that form and `scalar_ok` to hold.
Chez's character constructors exclude surrogates, but that the strings
reaching Shen satisfy this is an obligation (OB-REPR-STRING-SCALARS).

**Registers used by generated code** (`arm64.ss` `define-registers`):

| Register | Use |
|---|---|
| x19 | `%tc` (thread context) |
| x20 | `%sfp` (Scheme frame pointer) |
| x21 | `%ap` (allocation pointer) |
| x22 | `%trap` (event counter) |
| x23 | `%ac0` (argument count on entry, return value) |
| x24 | `%xp` |
| x8 | `%ts` |
| x25 | `%td` |
| x26 | `%cp` (closure pointer) |
| x10 | `%jmptmp` |
| x30 | `%lr` |
| x31 | `%sp` |
| x0, x1, x2 | argument registers (`asm-arg-reg-cnt` 3) |

The thread context offsets for the spilled registers are in `ChezLayout.v`
(`tc_ac0_disp` 0x70, `tc_sfp_disp` 0x80, `tc_ap_disp` 0x98, ...). The
return-point layout (`return_address_*_disp` -32..-8) is pinned too, but no
lemma uses it yet.

## 3. Rocq: the Chez representation relation

The constants are in `rocq/ChezLayout.v` (generated). `rocq/ChezWord.v`
holds the fixnum facts. It uses only the Coq standard library, so the same
file also compiles under Coq 8.19 for the Islaris corollary.
`rocq/ChezRepr.v` holds the relation.

The relation is `rv m loc proc port cond : value -> Z -> Prop`. It is defined
over a byte memory `m`, a vector-location map `loc`, and three meaning
parameters for closures, ports and conditions. Its constructors are:

* `RFix` (z in range, the word is `fx_enc z`) and `RBig` (z out of range,
  canonical bignum);
* `RFlo`;
* `RTrue`, `RFalse`, `RNil`;
* `RSym` (symbol whose name field is a string of the name);
* `RStr`;
* `RCons` (pair whose car/cdr words represent the components);
* `RVec` (`loc l` with a vector header);
* `RProc` (closure shape with a code object, plus `proc`);
* `RStream` (port, plus `port`);
* `RExn` (record, plus `cond`).

`heap_rel` relates the vector heap: `loc` is injective, and each location's
cells sit in a vector object with the right length and element words.

Every theorem is closed under the global context, and the count is 45 in
`rocq/Audit_Repr.v`. The section parameters are universally quantified;
none is an axiom.

| Theorem | Statement | Kind |
|---|---|---|
| `chez_fixnum_layout`, `chez_word_layout`, `chez_object_layout`, `chez_register_layout`, `chez_fields_aligned` | the pinned constants are mutually consistent (`fixnum_bits + fixnum_offset = ptr_bits`, ranges, register numbers, aligned field displacements) | ground |
| `chez_sources_agree` | every literal `cmacros.ss` constant equals `equates.h`; the `TYPE` macro subtracts `typemod`; the build is tarm64le, threaded, little endian | ground |
| `fx_enc_tagged`, `fx_enc_word` | every fixnum encoding is a 64-bit word with tag 0 | universal |
| `fx_dec_enc`, `fx_enc_inj` | decode∘encode = id on the fixnum range; the encoding is injective | universal |
| `fx_enc_dec` | every tag-0 word is the encoding of exactly one fixnum | universal |
| `fx_add_wrap` | `(fx_enc x + fx_enc y) mod 2^64 = fx_enc (x + y)` | universal |
| `fx_add_no_overflow_iff` | for fixnums x, y: signed 64-bit `fx_enc x + fx_enc y` does not overflow iff x + y is a fixnum | universal |
| `tag_or_iff`, `fx_or_tag` | `(a\|b)&7 = 0` iff both are fixnum-tagged | universal |
| `ptr_tag`, `field_aligned` | a t-tagged pointer has primary tag t; fields at displacements of the right residue are 8-aligned | universal |
| `rv_classify` | a total decoder `classify` (tag, then type-word bits) returns `vkind v` for every `rv v w` | universal |
| `rv_kind_unique` | one word never represents two kinds of value (tag decoding injectivity) | universal |
| `immediate_pointer_disjoint` | pointers are never immediates, fixnums, `#t`, `#f` or `'()` | universal |
| `non_values_unrepresented` | no Shen value is represented by void, unbound, eof, bwp, the black hole or the forward marker | universal |
| `rv_functional` | with `loc` injective, a word represents at most one first-order value (decoding is a function) | universal |
| `car_cdr_repr`, `string_ref_repr`, `string_length_repr`, `vector_ref_repr`, `heap_rel_vec` | car/cdr, string-ref/length and vector-ref/length on the representation read the abstract components; field addresses are aligned | universal |
| `shen_int_tag_test` | for words representing Shen integers x, y: `(a\|b)&7 = 0` iff both x and y are fixnums | universal |
| `shen_int_add_fast_path` | under that tag test, a = `fx_enc x`, b = `fx_enc y`, no-overflow iff x + y is a fixnum, and then `(a+b) mod 2^64` represents x + y | universal |
| `chez_sample_agrees` | the emulated sample words equal the encodings (pair car/cdr, `#t/#f/'()/void`, vector/string/bignum headers, string-chars, bigits of 2^70, flonum bits of 1.5, pointer residues, closure entry offset) | **sampled** (one process) |

Four proof mutations (`tests/mutate-repr.py`) must be refused:

* a 2-bit fixnum shift in the capture;
* a `TYPE` macro without `-typemod`;
* a changed sample string-char;
* the naive claim that two Shen fixnums never overflow when added. Rocq
  rejects this one with `Cannot find witness`: the fast path's overflow
  premise is genuinely stronger than "a and b are Shen integers".

## 4. The Islaris fast path as a statement about Shen values

`ports/arm/islaris/buri_chez_add_shen.v` is checked by
`ports/arm/islaris/check-islaris-shen.sh ENV TRACES`. It is an
**Islaris theorem**: Coq 8.19.0 in `nix/arm/islaris.nix`, outside
`scripts/prove`. It compiles the same `rocq/ChezLayout.v` and
`rocq/ChezWord.v` as `scripts/prove`, under the logical path `Buri`. It
passes against both stored trace sets, `instructions/buri_chez_add` (isla
`b8e614bd`) and `instructions/buri_chez_add-isla-e9b5d945`.

`buri_chez_add_shen` uses the nine captured instructions and the two
`instr _ None` slow-path targets. Under these premises:

* X0 = `fx_enc x` and X1 = `fx_enc y`, with x, y and x + y in the fixnum
  range;
* X23 = 2 (`%ac0`, the argument count);
* X20 (`%sfp`) is an aligned frame slot below 2^52 holding `ra`.

Then the code reaches `ra` with X23 = `fx_enc (x + y)`, X30 = `bv_or` of the
operands, X10 = `ra`, and X0, X1, X20 and the slot unchanged.

The proof applies `buri_chez_add_fast_path` through `instr_pre_wand`. It
discharges the two premises from the Shen-level ones:

* `fxw_tag_test` discharges `(a|b)&7 = 0`;
* `fxw_no_overflow_iff` discharges `-2^63 ≤ sa + sb < 2^63`: it holds
  **iff** x + y is a fixnum.

`chez_regs_match` checks that the register names X23/X20/X0/X1/X30/X10 and
the mask 7 used in the spec equal the extracted `reg_ac0`, `reg_sfp`,
`reg_arg1/2`, `reg_lr`, `reg_jmptmp` and `mask_fixnum`. `Print Assumptions`
reports **Closed under the global context** for `buri_chez_add_shen` and for
`fxw_no_overflow_iff`. Together with `ChezRepr.rv_fix_word` (a fixnum-range
Shen integer is represented only by `fx_enc z`), the theorem is about Shen
integers and not about arbitrary tagged words.

What remains assumed is exactly what `buri_chez_add.v` assumes:

* Islaris's register constraints: EL2, `SCTLR_EL2`, MMU off, `HCR_EL2`, ...;
* the isla `b8e614bd` traces over the Armv8.5 IR, with isla and z3 trusted;
* the captured base address;
* the continuation `instr_pre ra`, since the Chez return protocol is not
  modelled.

Chez runs at EL0 under Linux with the MMU on. That relation is
OB-REPR-ISLARIS-CONTEXT (E2E-20/27/31).

Two premises are kept rather than discharged. The frame-slot premises on X20
are Chez stack-frame representation facts (OB-REPR-CHEZ-FRAMES, E2E-22). The
operand-in-range premises are Shen facts: when x + y is not a fixnum, the
code takes the `bvs` slow path into the library `+` (E2E-24), which this
theorem does not cover. The link between the two kernels (Coq 8.18 in
`scripts/prove`, Coq 8.19 Islaris) is that both check the same source text.
No proof connects the kernels.

## 5. SBCL 2.6.8 arm64: representation relations and the E2E-21 host operations

`rocq/SbclLayout.v` holds the generated layout values. `SbclRepr.sbcl_source_matches_image`
is a ground derivation: the lowtag, widetag and register values evaluated
from source equal those captured from the pinned image.
`sbcl_layout_facts` records the layout facts below.

Feature set (image capture): `64-bit arm64 sb-thread sb-unicode`, plus the
internal features `sb-simd-pack`, `soft-card-marks`, `compare-and-swap-vops`
and others. `compact-instance-header`, `sb-simd-pack-256` and
`sb-simd-pack-512` are absent.

| Kind | Representation |
|---|---|
| Word | 64 bits; `n-lowtag-bits` 4, lowtag mask 15; `n-widetag-bits` 8 |
| Fixnum | `n << 1`, `n-fixnum-tag-bits` 1 (every even lowtag is a fixnum lowtag); range [-2^62, 2^62-1]. Unlike Chez, the fast-path tag test is `(a\|b)&1 = 0` |
| Lowtags | instance-pointer 3, list-pointer 7, fun-pointer 11, other-pointer 15; other-immediate 1/5/9/13 |

| Widetags | bignum 0x11, ratio 0x15, single-float 0x19 (immediate on 64-bit: `bits << 32 \| 0x19`), double-float 0x1D, symbol 0x2D, instance 0x39, simple-fun 0x41, closure 0x45, character 0x51 (immediate: `code << 8 \| 0x51`), simple-vector 0x89, simple-base-string 0xE1, simple-character-string 0xE5 |

### 5.2 The captured code (rocq/SbclA64.v, rocq/SbclTests.v)

`SbclA64` is a decoder and integer semantics for the A64 forms the windows
use: AND/ANDS/ORR (immediate, with DecodeBitMasks; shifted register),
ADD/SUB/SUBS (immediate, shifted register), CCMP (register), CSEL,
TBZ/TBNZ, B.cond, B, LDURB, and, for frame checks only, LDR/STR/LDP/RET.
Flags are AddWithCarry; register 31 is ZR where the architecture says so and
every SP use is refused; unsupported words decode to `None` and an
unsupported step stops `run`. **This transcription of the Arm ARM is a trust
boundary** (OB-SBCL-INLINE-TESTS); it is not checked against the Sail model.

All ten E2E-21 operations are inline type tests in the pinned image:

| Operation | Window (decoded from the captured words) | Word-level test |
|---|---|---|
| EQ | `CMP R2, R1`; T/NIL by `CSEL EQ` | `x = y` |
| TYPEP FIXNUM | `TST R1, #1` | bit 0 clear |
| INTEGERP | `TBZ R1,#0`; lowtag 15 and header byte 17 | fixnum or bignum |
| NUMBERP | `TBZ`; `CMP W1, #25` (single float); lowtag 15 and header ≤ 41 | |
| CONSP | `AND #15; CMP #7; CCMP R1, NULL` | lowtag 7 and not NIL |
| STRINGP | lowtag 15 and `header - 225 ≤ 12` unsigned | header in [225, 237] |
| ARRAYP | lowtag 15 and header ≥ 129 (signed `B.GE`) | |
| SYMBOLP | `CMP R1, NULL` first; then lowtag 15 and header 45 | NIL or symbol |
| NOT, NULL | `CMP R1, NULL` (identical code, `not_null_same_code`) | `w = NIL` |

`SbclTests.*_window` are **universal theorems**: for every register file in
which the argument register holds any word and x26 holds NIL, and every
memory, the decoded window reaches its end with x10 = T or NIL exactly as the
word-level test says. `frame_ground` (ground) checks each captured function
is the standard external entry (argument count check, the argument moved from
R0), the window, and the single-value return. `full_calls` (ground) shows
STRING=, EQUAL, EQL and `=` end in an indirect tail branch through a function
object: they are full calls, and their contracts stay with E2E-24.
`tests_match_sources` (ground) shows that on every header widetag of the
early-objdef enumeration the captured INTEGERP, NUMBERP, STRINGP and symbol
header tests agree with the define-type-vop type codes. ARRAYP's code list is
computed from the saetp table and is not lifted; its test is `≥
simple-array-widetag` (129), and widetag 253 (`unused-array`) is no object's.

The captured functions take an **untyped** argument. SBCL emits shorter code
when it has derived a type (type-vops.lisp branches on the TN type); those
variants, and whether the Shen-CL call sites use the untyped one, are
OB-SBCL-INLINE-TESTS.

### 5.3 NIL

genesis.lisp (pinned; flags in `sbcl_source_flags`) lays NIL out so that its
word (lowtag 7, a list pointer) is its symbol descriptor plus 8 (an
other-pointer descriptor `des = NIL - 8`), its car and cdr (`NIL - 7`,
`NIL + 1`) are NIL, and the byte at `NIL - 15` is symbol-widetag.
`SbclValues.nil_dual` proves, from that layout as a snapshot premise: CONSP
is false on NIL, NULL and SYMBOLP true, and the generic other-pointer symbol
test is false on NIL, which is why the captured SYMBOLP compares with NULL
first.

How Shen values land on it: Shen `[]` is NIL; Shen `true` and `false` are the
symbols `true`/`false` (Shen-CL's `shen-cl.true?`), so

* SYMBOLP is T on Shen `[]` and on both Shen booleans (`kl_tests`,
  `kl_machine_tests`): Shen `symbol?` cannot be the raw CL SYMBOLP;
* NULL and NOT are NIL on Shen `false` (`kl_false_is_cl_true`): Shen false
  is CL true;
* the word of `VBool b` also represents `VSym` of its name
  (`kl_bool_symbol_collision`): unlike Chez, the KLValue relation is not a
  function on words. A Shen symbol whose CL interning is NIL itself has no
  representation (the relation requires an ordinary symbol object).

### 5.4 The relations

`SbclWord` (universal, plus the ground `sbcl_word_layout`): fixnum encoding,
round trip, injectivity, every even word a fixnum, wrapping add, the
no-overflow iff, `(a|b)&1 = 0` iff both fixnums, slot alignment.

`SbclValues.kv` relates KLValue values to words over a byte memory `m`, a
vector-location map `loc`, a symbol table `symw` and meaning parameters
`proc`, `port`, `cond`: fixnums, normalised bignums, double-floats, NIL,
interned symbols (booleans as their symbols), strings (simple-character or
simple-base, fixnum length, scalar code points), conses, simple-vectors at
`loc l`, function objects (simple-fun, closure, funcallable instance) and
instances (streams, conditions). `heap_rel`, `car_cdr_repr`,
`vector_ref_repr`, `immediate_pointer_disjoint` and `kl_tests` are proved.

`SbclHostOps.cv` relates the CL-model values `sv` of CLLowering to words in a
snapshot (memory, symbol table, host-object words and kinds, float
spellings): NIL, symbols, strings, canonical integer spellings as fixnums or
bignums, other number spellings as double-floats or single-float immediates,
host objects as simple-vectors, functions, instances or characters, conses.
`snap_wf` requires injective interning, object identity and float spellings,
T at NIL + 56 and the genesis NIL layout; `ex_snap_wf` exhibits one.
`cv_functional` proves a word represents at most one `sv`.

### 5.5 E2E-21 host operations discharged

`e2e21_machine`: for every well-formed snapshot, every `sv` value and every
word representing it, the captured code for CONSP, NULL, NOT, SYMBOLP,
STRINGP, NUMBERP, INTEGERP, TYPEP FIXNUM and ARRAYP returns the word that
represents exactly the cl_host_ops answer. `eq_machine`: EQ's answer is the
word identity, sound, and complete when either side is a symbol or NIL; EQ is
not a function of `sv` values (one cons compared with itself is T, two equal
fresh conses NIL).

`sbcl_host` is the host table whose ten E2E-21 entries are those answers
(EQ: any admissible answer `e`) and whose other entries are a table `h24`.
`sbcl_host_ops` proves `cl_host_ops (sbcl_host K e h24)` from
`cl_e2e24_ops h24` (STRING=, EQUAL twice, EQL vs `=` on integers, `=`
symmetric, `=` reflexive) and `eq_admissible e`; `sbcl_host_is_machine`
proves its entries are the captured code's answers on every representation.
`sbcl_optimise_sound` / `sbcl_emit_if_refines` restate
CLContracts.discharged_optimise_sound / discharged_emit_if_refines for that
host; the `_e24` corollaries fix `e := eq_fresh` and leave exactly
`cl_e2e24_ops` and `cl_kernel_ops` (plus `qsafe`) as premises.
`e24_satisfiable` is anti-vacuity only (CLContracts.model_host, not SBCL).

Every statement is closed under the global context: 72 in
`rocq/Audit_Sbclnative.v`. Five proof mutations (`tests/mutate-sbclnative.py`)
must be refused: the consp CCMP condition flipped in the capture, a string
test claimed to accept the symbol widetag, NIL claimed not a symbol, Shen
false claimed CL false, and EQ claimed complete on all equal values.

What this does not give: the A64 transcription is trusted; only the untyped
compile of each operation is covered; frames, calling convention and the
return protocol (E2E-22); that Shen-CL and primitives.lsp keep values inside
the relation; GC, allocation and threads (E2E-25/28); symbol names and
packages (the relation uses a symbol table); bignum normalisation by SBCL
arithmetic; float meaning; characters beyond scalars (OB-REPR-SBCL-CHARS).

## 6. Discovered disagreement: `intern` of numeric names on Shen-Scheme

Shen-Scheme v0.52 `kl:intern` (`src/primitives.scm`, commit `fa071737`) maps
a name of length > 1 whose first character is a digit through
`string->number`. On the pinned host binary, `(intern "12")` is the integer
12, not a symbol (**sampled**, `tests/representation.shen`). The model's
`rule_intern` (`rocq/KLSemantics.v`) yields `VSym "12"`. The obligation
OB-SCHEME-INTERN-NUMERIC is recorded as **refuted** by this counterexample.
Its successor is OB-SCHEME-INTERN-ADMISSION (E2E-17): admit only non-numeric
names, or change the profile.

## 7. What is not proved, and who owns it

These items are open; none is assumed away:

* **Closures, continuations, frames, multiple values** (E2E-22). The relation
  fixes only closure shape, and `proc` carries the meaning (OB-REPR-CHEZ-CLOSURES).
  The stack frame, return-address and live-mask protocol (the X20 premise),
  multiple values and `call/cc` are unmodelled (OB-REPR-CHEZ-FRAMES).
* **Globals and symbols** (E2E-24). Interning uniqueness, the name-field
  invariant and how Shen-Scheme stores global values and functions
  (OB-REPR-CHEZ-SYMBOLS).
* **Bignum normalisation** (E2E-24). `RBig` requires out-of-range z. Every
  Chez integer operation must return normalised results
  (`S_normalize_bignum`; OB-REPR-CHEZ-BIGNUM-NORMAL).
* **Flonums** (E2E-17). Bits are related, but their meaning waits on the
  numeric profile (OB-REPR-CHEZ-FLONUM-PROFILE).
* **Ports and conditions** (E2E-27, E2E-17). The `port` and `cond`
  parameters (OB-REPR-CHEZ-PORTS, OB-REPR-CHEZ-CONDITIONS).
* **Allocation and GC** (E2E-25). The relation is about one snapshot. Moving
  collection must update `loc` and every word consistently; write barriers
  and card marking on `vector-set!` are not covered (OB-REPR-CHEZ-GC, which
  depends on OB-GC-CORRECTNESS and OB-HEAP-REPR-INVARIANT).
* **Ownership across asynchronous events** (E2E-28). The `%trap` event
  counter, signals, other pthreads and the memory model (OB-REPR-OWNERSHIP-ASYNC).
* **FFI and IO boundary values** (E2E-24, E2E-27). Foreign pointers,
  bytevectors and decoded strings (OB-REPR-FFI, OB-REPR-STRING-SCALARS).
* **Shen-Scheme actually staying inside the relation** (E2E-15/22). No
  theorem says that compiled Shen code only produces related words. The
  VALUE-MODEL `cond` sample returns `#<void>`, which `non_values_unrepresented`
  shows has no meaning (OB-REPR-SHEN-SCHEME-PRESERVES).
* **The CL relation** (E2E-21). Defined and its basic properties proved
  (section 5); partial: frames, GC, symbol names, Shen-CL preservation and
  the inline-test compilation boundary remain (OB-NATIVE-REPR-SBCL,
  OB-SBCL-INLINE-TESTS).

E2E-21 stays in progress. Its exit criterion ("all native values and memory
accesses used by the admitted execution paths have justified meanings") is
not met.
