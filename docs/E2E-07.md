# E2E-07: the executable Shen reference evaluator refines the KLambda semantics

Status: **in progress**. This note records what is proved about the *actual*
`shen/klambda.shen` (profile BURI/KL-PURE-1) against the Wave-A formal KLambda
semantics (`rocq/KLSyntax.v`, `KLValue.v`, `KLSemantics.v`,
`KLMetatheory.v`; obligations listed in [KLAMBDA-SEMANTICS](KLAMBDA-SEMANTICS.md)).
It is a theorem about that evaluator as compiled and installed by the pinned
Shen-Scheme image and executed by the Native model; it is not a theorem about
Shen-Scheme, Chez, the Shen frontend, or any port.

## What is proved about which code

**Capture.** `make prove` runs `buri.observe-constructor` on
`shen/klambda.shen` (profile `e2e07_klambda`, all 26 definitions in source
order), diffs the bits, transcript and source copy against
`ports/e2e07-klambda.bits*`, repackages them with
`scripts/package-provenance.py` (chunked literal, checked by
`check-provenance-package.py`) and diffs `rocq/KLambdaEvaluatorInput.v`.
`e2e07_klambda_exact/_names/_complete` decode every definition. Python only
moves bytes.

**Executed program** (`KLambdaEvaluatorCapture.program`): the capture, plus the
captured `base.shen` (`buri.get`, `buri.member?`, `buri.unique?`,
`buri.nat?`, `buri.exact-integer?`, ...) and `kernel.shen` (`buri.zip`)
programs of EQ-1, plus the pinned runtime helper templates (`kl:=` is
`equal?`, `kl:_scm.assert-boolean`, `kl:symbol?`, `kl:str`) and the contract
`kl:not = (if x #f #t)`, exactly as for EQ-1. `program_names_unique` checks
there is no shadowing. `kl:length` and `kl:shen.f-error` are **not** modelled:
a run that reaches them has no Native value, so every theorem is silent about
it. `native_run_ask` connects the actual fuelled `Native.run` to the
fuel-free oracle semantics (`EqualityInductionOracle.eval_oracle`).

**Representation.** `rv`/`term` are klambda.shen's own runtime values and inert
syntax, `enc`/`enc_term`/`enc_env` their exact Shen list shapes (`[int N]`,
`[closure X E Env]`, `[[X V] | Env]`, ...). The representation relation to
KLValue is the function `tr_rv` (pointwise on environments, `tr_env`):

| klambda.shen | KLambda value |
|---|---|
| `[int N]`, `[bool B]`, `[str S]`, `[sym S]`, `nil`, `[pair A B]` | `VNum (NInt N)`, `VBool B`, `VStr (of_string S)`, `VSym (of_string S)`, `VNil`, `VCons` |
| `[closure X E Env]` | `VLam X (tr E) (tr_env Env)` |
| `[function F Args]` | `VPartial ("user:" ++ F) Args` (stated; not in the proved subset) |
| `[thunk E Env]` | `VFrozen (tr E) (tr_env Env)` (stated; not in the proved subset) |

Syntax translation `tr`: `[literal V]` is the literal (a pair literal is
`(cons a b)`), `[var X]` is `EVar`, `[lambda X E]`/`[let X A B]`/`[if C A B]`
are `ELam`/`ELet`/`EIf`, `[apply F A]` is the one-argument computed call
`EApp F [A]`, `[primitive Op Args]` is the direct call `ECall Op Args` (the
store binds the primitive names, `prims`), `[raise E]` is
`(simple-error E)`, and `[trap E H]` is `ETrap E (handler H)` where the handler
wrapper evaluates `H` after the exception, in the trap's own environment, and
applies it to `(error-to-string exn)`: klambda.shen hands the handler the
message string, KLambda hands it the exception value.

**Verdicts** (`verdict`, `enc_verdict`):

| klambda.shen | KLambda (`KLMetatheory.run`) |
|---|---|
| `[returned V]` | `VDone [] (Normal (tr_rv V))` for some fuel; terminating behavior, no divergence |
| `[raised M]` | `VDone [] (Error x)` with `exn_class M x`; terminating, no divergence |
| `[unknown evaluation-budget]` | no claim (exhaustion is not a behavior; never read as divergence) |
| `[unsupported closure-equality]` | no claim (see disagreements) |
| `[rejected ...]` | admission, outside the semantics (from `buri.evaluate` only) |
| `[unknown host-error]` | **no counterpart**: only the guard handler of `buri.evaluate` produces it (`evaluate_shape`) |

`exn_class` (many-to-one): `XUser (of_string M)` for any `M` (a user raise of
the same text); `"unbound-variable"` is `XUnboundVar _`;
`"nonboolean-condition"` is `XNotBoolean`; `"not-callable"` is
`XNotCallable`; `"error-message-not-string"` is `XPrim PSimpleError`;
`"primitive-domain-or-arity"` is `XPrim p` with `p <> PSimpleError`.

**Profile premises** (`pure P`, `prims s`): no modeled stack bound, and the
system-error message slot `sys_message` maps each class above to its
klambda.shen text (observable through `trap`); the store binds the eleven
primitive names plus `simple-error` and `error-to-string`. They are premises,
not axioms, and are satisfiable (`pure_profile_ok`, `prim_store_ok`).

## Evidence, by kind

Universal theorems (axiom-free, in `rocq/Audit.v`):

* `KLambdaEvaluatorRefinement.klambda_refines` — for every `e` with `sub e`
  (KL-PURE-1 subset: literals, variables, `lambda`, `apply`, `let`, `if`,
  saturated `+ - * < = cons hd tl cons? number? string?`, `raise`, `trap`),
  every definition table `D`, budget `z` and Native fuel `n`: if
  `Native.run n program "kl:buri.eval" [D; e; []; z]` returns `r`, then
  `r = enc_verdict w` and, under every `pure` profile and `prims` store, the
  KLambda run of `tr e` in the empty environment returns the translated
  verdict (table above) for some fuel; by `run_monotone`, for every larger fuel.
* `klambda_decided_terminates` — the same verdicts as `Terminates` behaviors of
  the closed system, which therefore cannot also diverge
  (`closed_terminates_excludes_divergence`).
* `klambda_refines_open` — the compositional form: any oracle fuel, any
  environment of related values, any continuation.
* `evaluate_shape`, `evaluate_body_refines` — the captured `buri.evaluate` is a
  Chez `guard` whose handler is the literal `[unknown host-error]` and whose
  body admits and calls `buri.eval` with `[]`; every value of that body is
  `[rejected ...]` or a sound verdict.
* `KLambdaEvaluatorEquations.*` — one equation per captured body and input
  shape (the reflective, compositional per-construct lemmas); and
  `KLambdaEvaluatorPrimitives.ask_prim1/ask_prim2/ask_prim_equal/ask_literal`.
* Machine side: `m_*`, `ap_*`, `args_*`, `kl_prim`, `kl_prim_equal`,
  `kl_eq_data` (structural `=` on literal data is `equal?`).

Ground derivations (`KLambdaEvaluatorSamples`, vm-checked on the actual
captured program): `let`, `trap` of a raise, non-Boolean `if`, higher-order
application, budget exhaustion, closure equality; `sample_let_machine`
instantiates the universal theorem; `sample_let_kl` is an independent KLambda
computation that agrees. These are ground, not universal, evidence.

Proof technique: each captured body is unfolded once and reduced by the VM
with the callee oracle abstracted as a variable (`ask_unfold` + `generalize`),
so the Native primitive table (a large string match) is never reduced by
`cbn` and no large proof term is built; Qed checks are VM casts. All six
modules compile in well under a minute (the EQ-1 Ltac executor did not finish
`substitution?` in ten minutes).

## Disagreements and profile differences

None required changing `shen/klambda.shen` (so `make conformance` was not
triggered); each is a stated profile difference with an owner, never a
weakened theorem.

* **cond fall-through (Scheme `#<void>`).** klambda.shen has no `cond` form.
  Every `cond` in its compiled code ends in a `true` clause: `Native.decode`
  rejects a `cond` whose last clause is not `true`, and `e2e07_klambda_exact`
  shows the whole capture decodes. So the evaluator itself cannot fall through.
* **E2E07-EQ-CLOSURE.** `(= closure data)`: klambda.shen answers
  `[unsupported closure-equality]` when either side is not literal data;
  `KLValue.kl_eq` answers `false` unless both sides are functions. Soundness
  holds (unsupported makes no claim); completeness fails here. Owner E2E-05/E2E-07.
* **E2E07-PRIM-ARITY.** `[primitive Op Args]` with the wrong arity raises
  `primitive-domain-or-arity`; a KLambda call curries (`VPartial`) or
  over-applies. Outside `sub` (only saturated calls are translated). Owner E2E-07.
* **E2E07-THAW.** `[thaw E]` of a `[function ...]` value is `not-frozen` in
  klambda.shen but a partial application under `EApp E []`; `[apply]` of a
  thunk is `not-callable` while KLambda raises `XArity`, which `trap` can
  observe through the message text. `freeze`/`thaw` are outside `sub`.
* **E2E07-GLOBAL.** `[global X]` and `[function ...]` application go through
  `buri.apply-global`, which calls the uncaptured runtime `kl:length`, and
  need the user-namespace translation (`fname`, prefix `user:`) to be related
  to a store holding the definitions. Outside `sub`.
* **E2E07-GUARD.** `trap-error` in `buri.evaluate` compiles to a Chez `guard`;
  the Native model has no guard, so "guard returns its body's value when the
  body returns" is a stated contract, as EQ1-GUARD.

## Open obligations

* **E2E07-COMPLETE** (converse): if the KLambda run of `tr e` terminates, then
  with sufficient budget the captured evaluator returns the corresponding
  verdict. Needs Native-level termination of the captured code (Native fuel,
  not oracle fuel) and fails for E2E07-EQ-CLOSURE; not proved.
* E2E07-GLOBAL, E2E07-THAW, E2E07-PRIM-ARITY, E2E07-EQ-CLOSURE, E2E07-GUARD
  (above); `[global]`, `[freeze]`, `[thaw]` are named, not dropped.
* **E2E07-NATIVE**: Chez-to-Native simulation, as for every Native result (E2E-32).
* The Shen admission predicates (`buri.expression?`, `buri.definitions?`) are
  not related to `sub`; the theorem quantifies over all `sub` terms, admitted
  or not, so admission can only reject.
