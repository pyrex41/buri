# E2E-07: the executable Shen reference evaluator refines the KLambda semantics

Status: **in progress** (soundness for every KL-PURE-1 construct and its converse are proved; guard, Native simulation and admission correspondence remain open). This note records what is proved about the *actual*
`shen/klambda.shen` (profile BURI/KL-PURE-1) against the Wave-A formal KLambda
semantics (`rocq/KLSyntax.v`, `KLValue.v`, `KLSemantics.v`,
`KLMetatheory.v`; obligations listed in [KLAMBDA-SEMANTICS](KLAMBDA-SEMANTICS.md)).
It is a theorem about that evaluator as compiled and installed by the pinned
Shen-Scheme image and executed by the Native model; it is not a theorem about
Shen-Scheme, Chez, the Shen frontend, or any port.

## What is proved about which code

**Capture.** `make prove` runs `buri.observe-constructor` on
`shen/klambda.shen` (profile `e2e07_klambda`, all 33 definitions in source
order), diffs the bits, transcript and source copy against
`ports/e2e07-klambda.bits*`, repackages them with
`scripts/package-provenance.py` (chunked literal, checked by
`check-provenance-package.py`) and diffs `rocq/KLambdaEvaluatorInput.v`.
`e2e07_klambda_exact/_names/_complete` decode every definition. Python only
moves bytes.

**Executed program** (`KLambdaEvaluatorCapture.program`): the capture, plus the
captured `base.shen` (`buri.get`, `buri.member?`, `buri.unique?`,
`buri.nat?`, `buri.exact-integer?`, ...) and `kernel.shen` (`buri.zip`)
programs of EQ-1, plus the pinned runtime helper templates (`kl:=` is
`equal?`, `kl:_scm.assert-boolean`, `kl:symbol?`, `kl:str`) and the contract
`kl:not = (if x #f #t)`, exactly as for EQ-1. `program_names_unique` checks
there is no shadowing. The evaluator no longer calls `kl:length`
(`buri.fewer?` replaced it); `kl:shen.f-error` is **not** modelled: a run that
reaches it has no Native value, so every theorem is silent about it. `native_run_ask` connects the actual fuelled `Native.run` to the
fuel-free oracle semantics (`EqualityInductionOracle.eval_oracle`).

**Representation.** `rv`/`term` are klambda.shen's own runtime values and inert
syntax, `enc`/`enc_term`/`enc_env` their exact Shen list shapes (`[int N]`,
`[closure X E Env]`, `[[X V] | Env]`, ...). The representation relation to
KLValue is the function `tr_rv` (pointwise on environments, `tr_env`):

| klambda.shen | KLambda value |
|---|---|
| `[int N]`, `[bool B]`, `[str S]`, `[sym S]`, `nil`, `[pair A B]` | `VNum (NInt N)`, `VBool B`, `VStr (of_string S)`, `VSym (of_string S)`, `VNil`, `VCons` |
| `[closure X E Env]` | `VLam X (tr E) (tr_env Env)` |
| `[function F Args]` | `VPartial ("user:" ++ F) Args` (proved, KLambdaEvaluatorExtended) |
| `[thunk E Env]` | `VFrozen (tr E) (tr_env Env)` (proved, KLambdaEvaluatorExtended) |

Syntax translation `tr`: `[literal V]` is the literal (a pair literal is
`(cons a b)`), `[var X]` is `EVar`, `[lambda X E]`/`[let X A B]`/`[if C A B]`
are `ELam`/`ELet`/`EIf`, `[apply F A]` is the one-argument computed call
`EApp F [A]`, `[primitive Op Args]` is the direct call `ECall Op Args` (the
store binds the primitive names, `prims`), `[raise E]` is
`(simple-error E)`, and `[trap E H]` is `ETrap E (handler H)` where the handler
wrapper evaluates `H` after the exception, in the trap's own environment, and
applies it to `(error-to-string exn)`: klambda.shen hands the handler the
message string, KLambda hands it the exception value.

**Verdicts** (`verdict`, `enc_verdict`):

| klambda.shen | KLambda (`KLMetatheory.run`) |
|---|---|
| `[returned V]` | `VDone [] (Normal (tr_rv V))` for some fuel; terminating behavior, no divergence |
| `[raised M]` | `VDone [] (Error x)` with `exn_class M x`; terminating, no divergence |
| `[unknown evaluation-budget]` | no claim (exhaustion is not a behavior; never read as divergence) |
| `[unsupported closure-equality]` | the machine goes wrong at the equality (extended theorem); no claim in the pure-subset theorem |
| `[rejected ...]` | admission, outside the semantics (from `buri.evaluate` only) |
| `[unknown host-error]` | **no counterpart**: only the guard handler of `buri.evaluate` produces it (`evaluate_shape`) |

`exn_class` (many-to-one): `XUser (of_string M)` for any `M` (a user raise of
the same text); `"unbound-variable"` is `XUnboundVar _`;
`"nonboolean-condition"` is `XNotBoolean`; `"not-callable"` is
`XNotCallable`; `"error-message-not-string"` is `XPrim PSimpleError`;
`"primitive-domain-or-arity"` is `XPrim p` with `p <> PSimpleError`.

**Profile premises** (`pure P`, `prims s`): no modeled stack bound, and the
system-error message slot `sys_message` maps each class above to its
klambda.shen text (observable through `trap`); the store binds the eleven
primitive names plus `simple-error` and `error-to-string`. They are premises,
not axioms, and are satisfiable (`pure_profile_ok`, `prim_store_ok`).

## Implementation changes (Wave C)

Four disagreements were resolved by changing `shen/klambda.shen` to agree with
the agreed semantics; `make conformance` passes (sampled agreement with
Shen-Scheme, including new equality cases), and the capture, packaging name
list and every E2E-07 module were regenerated and re-proved.

* **Equality (was E2E07-EQ-CLOSURE).** `buri.equal` implements `KLValue.kl_eq`:
  pairs left to right, a function value (`[closure ...]`, `[function ...]`,
  `[thunk ...]`) is unequal to every non-function value, and equality of two
  function values is undefined, answered `[unsupported closure-equality]`. On
  the KLambda side that is exactly the machine going wrong
  (`rule_equal` yields `Wrong "equality-undefined"`), which the extended
  theorem now states (`reaches2 WUnsupported`) instead of making no claim.
* **Arity (was E2E07-THAW).** `[thaw E]` of a closure and `[apply]` of a thunk
  raise `"arity"` (KLambda `XArity`); `[thaw E]` of a `[function F Args]`
  partial application returns it (KLambda `call_named` with no new argument);
  other non-callable values raise `"not-callable"`.
* **kl:length (was E2E07-GLOBAL).** `buri.apply-global` compared argument
  counts with the uncaptured runtime `length`; it now calls the captured
  structural `buri.fewer?`, so globals and function values are inside the
  captured program.
* **Saturated primitives (E2E07-PRIM-ARITY), a profile difference.** KLambda
  curries an under-saturated primitive call and over-applies the result of an
  over-saturated one. BURI/KL-PURE-1 keeps `[primitive Op Args]` a saturated
  direct call: `buri.expression?` (via `buri.saturated?`) rejects other arities
  at admission (`[rejected ...]`), and `buri.eval` itself still raises
  `primitive-domain-or-arity` for them, outside every theorem. This is recorded
  in the release charter as `profile_differences` entry
  `prim-partial-application` of feature `kl-currying`, owner E2E-07, with three
  registered enforcement tests; the ledger checker now checks such entries
  (owning package, at least one registered test; hostile ledger tests). It is
  not a theorem and not a weakened one: currying of user functions is proved.

## Evidence, by kind

Universal theorems (axiom-free; base names in `rocq/Audit.v`, new ones in
`rocq/Audit_E2e07b.v`):

* `KLambdaEvaluatorRefinement.klambda_refines` (and `_open`,
  `klambda_decided_terminates`, `evaluate_body_refines`) — unchanged statements
  for the pure subset `sub` with an arbitrary definition table, re-proved on the
  new capture. `kl_eq_tr`: KLambda equality of translated values is the
  evaluator's `eqv` for every value.
* `KLambdaEvaluatorExtended.klambda_refines_ext` — for every well-formed
  definition table `ds` (positive arity, bodies in the subset; `ds_ok`) and
  every term with `sub2 e` (all KL-PURE-1 constructs: literals, variables,
  `[global X]`, `lambda`, one-argument application of closures, partial
  applications and thunks, `let`, `if`, saturated primitives, `raise`, `trap`,
  `freeze`, `thaw`), every budget and Native fuel: a value returned by the
  captured `buri.eval` on `enc_defs ds` is a verdict `w`, and under every
  profile `pure2 P` and every store with `prims s` and `defs s ds` (the
  definitions translated into the global function namespace under `user:`
  names), the KLambda run of `tr e` returns `Normal (tr_rv v)` for
  `[returned v]`, `Error x` with `exn2 m x` for `[raised m]`, and goes wrong
  (`VWrong`) for `[unsupported closure-equality]`; budget makes no claim.
  `klambda_refines_ext_open` is the compositional form. Premises are
  satisfiable for every table (`pure2_profile_ok`, `defs_store_ok`).
* `KLambdaEvaluatorComplete.klambda_complete` — the converse: if
  `KLMetatheory.run` of `tr e` returns `VDone [] o` within `m` steps (a silent,
  terminating run), then for every budget `z > m` there is a fuel `n0` such
  that for all `n >= n0` the actual `Native.run n program "kl:buri.eval"`
  returns `[returned v]` with `o = Normal (tr_rv v)` or `[raised msg]` with
  `o = Error x`, `exn2 msg x`; never exhaustion or unsupported.
  `ask_run` connects the oracle semantics back to `Native.run`.
* Per-body equations: `KLambdaEvaluatorEquations.*`, `KLambdaEvaluatorGlobal.*`
  (global, freeze, thaw, apply-global, definition, zip, append, fewer?),
  `KLambdaEvaluatorPrimitives.ask_equal_rv/ask_prim_equal` (the captured
  `buri.equal` computes `eqv`), and forward (termination) equations
  `KLambdaEvaluatorForward.*`.

Ground derivations (`KLambdaEvaluatorSamples`): as before, plus
`sample_closure_data_eq` (`(= (lambda x x) 1)` is `false`) and
`sample_closure_eq` now on two closures. Ground, not universal, evidence.
Sampled agreement: `make conformance` (three new equality cases) and
`tests/evaluator.shen` (thirteen new cases). Proof mutations: six new false
ground claims about the captured evaluator (`tests/mutate-e2e07.py`) are
refused by Rocq.

Proof technique: unchanged (one unfolding per captured body, callee oracle
abstracted, VM reduction). The completeness proof is a strong induction on the
KLambda step count; each sub-answer is placed on the KLambda path by the
soundness theorem and the remaining step count follows by determinism
(`halts_taus`). Forward equations must generalize the callee oracle with
`generalize` and supply callee facts as hypotheses: a `remember`ed oracle
that survives into a VM cast makes the kernel normalize the unfolded oracle.

## Where completeness holds and where it does not

`klambda_complete` holds for the whole extended subset. Its boundary:

* Only silent terminating runs (`VDone [] o`); the subset has no IO, so this
  is every terminating run reachable from the translation.
* A budget larger than the KLambda step count is required; with a smaller
  budget the evaluator may answer `[unknown evaluation-budget]`, which is not
  a behavior (so completeness fails for small budgets by design).
* Runs that go wrong (equality of two function values) are not terminating
  behaviors; the evaluator answers `unsupported` there (soundness), and
  completeness is silent.
* Under-saturated or over-saturated `[primitive ...]` terms are outside `sub2`
  (profile difference above): there completeness fails, KLambda curries.
* The exception correspondence is many-to-one (`exn2`): `[raised "arity"]`
  matches a user `(simple-error "arity")` as well as `XArity`.

## Open obligations

* **E2E07-GUARD**: `trap-error` in `buri.evaluate` compiles to a Chez `guard`;
  the Native model has no guard, so "guard returns its body's value" stays a
  stated contract (as EQ1-GUARD).
* **E2E07-NATIVE**: Chez-to-Native simulation, as for every Native result (E2E-32).
* **E2E07-ADMISSION**: `buri.expression?`/`buri.definitions?` are not proved to
  coincide with `sub2`/`ds_ok`; the theorems quantify over all subset terms,
  admitted or not.
* `kl:shen.f-error` (pattern-match failure) is not modelled; a run reaching it
  has no Native value, so the theorems are silent there (it is unreachable on
  `enc_defs` tables and subset terms, but that is not proved).
